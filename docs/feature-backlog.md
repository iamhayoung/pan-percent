# Feature Backlog

将来の機能アイデア（実機反復で出たもの）。各項目に文脈と、対応する想定ブランチ／推奨案を残す。
visual/UX の微調整は `polish-backlog.md`、機能はここ。対象ユーザー像は memory `target-user-context` 参照。

## 詳細／編集の可読性・操作性（→ feature/recipe-form）

- パン作りの最中（手袋・粉の手）に使う前提で、詳細画面の**文字・タップ領域が小さい**との指摘。
- recipe-form で詳細＝編集を1つの直感的 input UI に統合する際、**文字大きめ・タップ領域大きめ・余白広め**で設計する。必要なら theme の fontSize/spacing 基準そのものを底上げ検討。
- 関連: 表示と編集を分けない統合 UI（memory `recipe-form-percent-editing`）。
- **削除ボタンの置き場所**: 詳細で「削除ボタンだけがポツンと1行ある」配置がしっくりこない、とユーザー。統合編集UIの再設計時に、削除の位置ごと見直す（例: ヘッダーにゴミ箱アイコン／編集導線の中に収める）。破壊的アクションは最大の的にしない（誤タップ防止）。

## 材料プリセット（→ 次フィーチャー）

- よく使う材料を毎回手入力せず、**プリセットから気軽に追加**したい。
- 例: 水 / 塩 / バター / 小麦粉各種（薄力粉・中力粉・強力粉）/ フランス系（T45・T55・T65 …）。
- `isFlour` の初期値もプリセットに含められる（小麦粉系は flour=true 既定）。粉/液体の区別が楽になる。
- 実装案: プリセット定義（多言語名 + isFlour）を持ち、フォームの材料追加時に選択 → 行に展開（g は後入力）。
- 粉のサジェスト（強力粉・全粒粉・ライ麦粉…）は本項目の具体化として進める。

## レシピのグルーピング／フィルタ（→ 一覧の拡張ブランチ）

- 現状タグは持てるが一覧での絞り込み・グルーピングが無い（本ブランチで意図的に defer）。
- **推奨案: タグのフィルタチップ**を一覧上部に置く（タップで該当タグのみ表示、複数選択可）。
  - 理由: レシピは複数タグを持てるため、「タグでセクション分割」だと1レシピが複数セクションに重複し分かりにくい。フィルタなら重複なく直感的。
  - タブ（recipes/settings）はトップ階層ナビ用なので、動的なタグをタブにするのは避ける。
- 将来: 「グループ表示」トグル等は必要になってから。

## 単位（g 以外 / 国別デフォルト）（→ recipe-form + settings-i18n）

- 材料ごとに **g 以外の単位**（ml, L など製パン・製菓でよく使う）を選べるようにしたい。材料により単位が違うため。
- 国によって基準が違う（g / ポンド lb / oz / L）。**設定画面で基本単位を選べる**ようにもしたい。
- **重要な設計注意 — ベーカー% は重量(g)基準**: 比率は「粉の総重量＝100%」で定義される。
  - **重量系（g / oz / lb）**: 相互変換は単純（比率＝重量比なので % は不変）。表示・入力単位の切替＋設定デフォルトは比較的容易。まずここから。
  - **体積系（ml / L）**: 重量とは密度が必要（水は 1ml≒1g だが油・牛乳・粉は異なる）。% に含めるには材料ごとの密度換算が要る。安易に混ぜると % 計算が壊れる。
  - 方針案: 内部は g 保存、表示/入力で単位変換。体積→重量は密度が要るため、対応材料を限定（例: 水）するか、材料に密度を持たせるかを recipe-form で設計判断。
- settings の「基本単位」は重量系の表示デフォルトとして settings-i18n で。
- **recipe-form での決着 (2026-06)**:
  - 主材料（粉 + % 計算対象の材料）: 重量系（g/kg/oz/lb）のみ。比率の正統性を守る。
  - 副材料ブロック（下記）: 自由単位（g/ml/個/大さじ・小さじ・カップ等）。% 計算対象外。
  - 「比率テンプレート型」（粉 0g で % を先に全部決めて後で粉量を決めるフロー）はサポートしない（公式上 % → g 逆算には粉重量が必須）。粉 0g のとき % 欄は disabled。

## 副材料ブロック（→ 次フィーチャー）

- ベーカー% に含めない材料（餡子・シュガーパウダー・トッピング・フィリング・デコ素材）を別ブロックで管理したい。
- 主材料との差異:
  - **% 計算対象外**（粉に対する比率を出さない）。
  - **自由単位**（上記「単位」参照）: g/ml/個/大さじ/小さじ/カップ など何でも。
- データモデル: `Ingredient` に `category: "flour" | "main" | "extra"` を追加するか、`isExtra: boolean` を足す（互換性的に後者が楽）。`extra` のときは `bakerPercents` の計算から除外、`scaleToFlour` のスケーリング対象からも除外（独立した量として保持）。
- UI: 編集フォームに「副材料」セクションを追加。先頭行は常に1つ表示、追加で行を増やせる、× で削除可。先頭行も「× を disabled で薄色表示」して列を整列（主材料と同じパターン）。
- 発見: `feature/recipe-form` 仕様議論時にユーザー指摘。

## タグの chips UI（→ 次フィーチャー）

- 現在は CSV テキスト入力（カンマ区切りで打つ）で、タグ感が薄く操作も面倒。
- 目指す形:
  - 既存タグはチップ形式で並ぶ（角丸 + 背景色 + ラベル + × ボタン）。
  - 末尾に点線の「+追加」ボタン。押すとインラインで入力 or モーダルで入力 → 確定で1つ追加。
- a11y: チップは `accessibilityRole="button"`、× は `accessibilityLabel`。
- 発見: `feature/recipe-form` 実機反復時のユーザー指摘。

## リスト画面の本文プレビュー（→ 一覧の拡張ブランチ）

- リスト画面のカードがタイトルとタグしかなく、レシピ同士の区別が付けにくい。
- 目指す形: Gmail 風に、タイトルの下に **1行 ellipsis で内容の手がかり** を表示。
- 候補:
  - 粉の総量 + 主要材料 2–3 個（例: 「粉 500g・水・塩・イースト…」）
  - or 加水率（hydration）と主要パン種類タグ（例: 「水分 70% · リーン系」）
  - or メモの先頭
- 一覧の拡張ブランチ（タグフィルタと同じスコープ）で UI と合わせて設計。
- 発見: `feature/recipe-form` 実機反復時のユーザー指摘。

## 写真追加機能（→ 次フィーチャー）

- レシピごとに写真（焼き上がり / 工程）を1枚以上添付できるようにしたい。
- 取得元: カメラ + ライブラリ（`expo-image-picker`）。Expo SDK 54 と互換。
- 保存: ローカル URI を AsyncStorage に `photoUri` として持つ既存型あり（`Recipe.photoUri?`）→ 単写真は型変更なしで実装可。複数写真化するなら `photoUris: string[]` に拡張。
- permission: カメラ・写真ライブラリそれぞれに `requestPermissionsAsync()` 必須。拒否時のフォールバック UI を用意。
- UI: 編集フォームに写真サムネ + 「+ 追加」ボタン（タップでアクションシート: 「カメラで撮る / ライブラリから選ぶ / 削除」）。詳細画面では大きく表示。
- 発見: `feature/recipe-form` 実機反復時のユーザー指摘。
